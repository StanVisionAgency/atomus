# AI: Approval

## Approval

Human-in-the-loop confirmation before an agent acts: the action as a question, a short summary, the risk level, a preview of what will be sent or changed, and Approve / Deny. People can edit the content before approving and can allow the action for the rest of the chat. After they decide, the card stays in the thread with the outcome. Part of the Agent kit.

Figma: planned component. The properties below are the Figma properties to come; React props already use the same names.

| Property | Type / options |
|---|---|
| Title | text |
| Summary | text |
| Risk | Low · Medium · High |
| Tool name | text |
| Details | slot (preview) |
| Editable | boolean (off) |
| Always allow | boolean (off) + label |
| State | Pending · Approved · Denied |
| Approve label · Deny label | text |

**Risk**

- **Low** — read-only or easy to undo; shield icon, success accent.
- **Medium** (default) — sends, posts or changes something people can fix; warning accent.
- **High** — deletes, pays, publishes or can't be undone; error accent and border. Name the action on the button ("Delete variables").

**Anatomy**

1. Accent bar on the left in the risk colour, and a risk icon tile.
2. Eyebrow: risk word ("High risk") and tool name.
3. Title (the question) and summary.
4. Details or editable preview.
5. Footer: "Always allow" checkbox; Deny, Edit, Approve.
6. Outcome after the decision: "Approved", "Approved with your edits" or "Denied".

**Use for**

- Any agent action that writes, sends, spends, deletes or shares.
- Steps the person may want to adjust before they happen (an email, a message, a list of issues).

**Not for**

- Read-only actions the person already asked for: just run them and show a Tool call.
- Confirming a person's own action in a form: use Modal.

**Accessibility**

- The card is a labelled region (`aria-labelledby` the title, described by the summary).
- Risk is a word and an icon, never colour alone.
- Focus is not moved to the card when it appears (Primer: keep focus stable); it is reachable in reading order and the buttons are standard buttons.
- The outcome is announced in a status region.

**Do**

- Phrase the title as a yes/no question with the scope: "File 3 issues in Linear?".
- Show exactly what will be sent or changed, and let people edit it when it is text.
- Keep the card in the thread after the decision so the record stays visible.
- Offer "Always allow" only for low- and medium-risk actions, scoped to this chat.

**Forbidden**

- Never run the action before the person approves.
- Never pre-tick "Always allow".
- Never offer "Always allow" for high-risk actions.
- Never use a vague label such as "OK" or "Continue" — say what Approve does.

# AI: Message and conversation

## Message

One turn in a conversation. The role sets the layout: user messages are right-aligned bubbles on `bg-tertiary`; assistant and tool messages flow full-width next to an avatar; system messages are a centred line between hairlines. Every message is an `<article>` named by its speaker, so it is always clear who said what. Part of the Agent kit.

Figma: planned component. The properties below are the Figma properties to come; React props already use the same names.

| Property | Type / options |
|---|---|
| Role | User · Assistant · System · Tool |
| Status | Streaming · Done · Error · Stopped |
| Name | text |
| Show name | boolean (on, off for User) |
| AI label | boolean (on) |
| Avatar | instance swap (Avatar) |
| Timestamp | text |
| Content | slot (text, Reasoning, Tool call, Approval, Sources) |
| Actions | Copy · Regenerate · Edit · Branch · slot (Feedback) |
| Actions visibility | Always · Hover |

**Anatomy**

1. Avatar: the AI mark on `bg-ai-subtle` for assistants, a wrench for tools, an Avatar for people.
2. Header: speaker name, AI label (assistants), timestamp.
3. Content slot: text, then any Reasoning, Tool call, Approval, Streaming text and Sources, in the order they happened.
4. Status notice: "You stopped this response." or an error with Retry.
5. Actions: branch switcher ‹ 1/3 ›, Copy, Edit (user), Regenerate (assistant), then the slot (Feedback).

**Use for**

- Chat threads, copilot panels and agent logs.
- Showing several agents in one thread: give each a distinct `name` and avatar.

**Not for**

- Person-to-person chat without AI: see the Messaging guidelines.
- Notifications and activity feeds: use the Activity item.

**Accessibility**

- Speaker clarity: the name is always in the accessible name of the article, even when hidden visually for user messages.
- Assistant messages carry the AI label, so AI content is never identified by colour or position alone.
- `status="streaming"` sets `aria-busy` on the article; the Streaming text inside announces the reply.
- Errors use `role="alert"`; Copy confirms "Copied to clipboard" in a status region.
- Icon-only actions have names ("Copy", "Regenerate response", "Edit message", "Previous version").

**Do**

- Name every speaker; use the product's assistant name rather than "AI".
- Keep the order of what happened: reasoning, then tools, then approvals, then the answer.
- Show actions on hover only in dense threads; they stay visible on touch screens and on focus.
- Keep the latest assistant message's actions visible.

**Forbidden**

- Never style assistant text as a bubble that looks like a person's message.
- Never remove the speaker name from the accessible name.
- Never show Regenerate on a user message or Edit on an assistant message.
- Never hide an error behind a toast — keep it in the message with a Retry.

## Conversation

The pattern that puts the Agent kit together: a header with the assistant's name, AI label and Context meter; a scrolling thread of Messages; and a Prompt input docked at the bottom. An empty thread shows a welcome state with prompt starters (Suggestions, `variant="cards"`). There is no Conversation component: compose it from the parts.

**Anatomy**

1. Header: assistant name, AI label with an explanation, Context meter, New chat.
2. Thread: `role="log"` region, max width about 720px, `spacing-3xl` between messages.
3. Welcome state: AI mark, one-line title, one sentence on what the assistant can do, 2–4 prompt starters.
4. Composer: Prompt input with the Model selector, and a disclaimer.
5. Follow-up Suggestions under the latest answer.

**Accessibility**

- Give the thread `role="log"` and an accessible name. Turn its own live announcements off (`aria-live="off"`) when Streaming text announces replies, so nothing is read twice.
- Make the scrolling thread focusable (`tabIndex={0}`) so keyboard users can scroll it.
- Keep focus in the Prompt input after sending; never move it to the new reply.
- Scroll new content into view inside the thread, not the whole page.

**Do**

- Say what the assistant can and can't do in the welcome state.
- Ask before acting: route every write or send through an Approval.
- Keep one primary button per view: Send, or Approve while an approval is pending.

**Forbidden**

- Never start a conversation with a wall of starters — four at most.
- Never auto-scroll while the person is reading earlier messages.
- Never stream into a region that also announces every token.
